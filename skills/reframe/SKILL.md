# Reframe

只在用户显式调用时执行。教用户用专业术语命名自己要构建的东西。直接从用户的原始文件、代码和原话出发，不依赖二手摘要。

如果用户的描述可能指向不止一个问题，先列出它可能是的 2 到 3 个问题：每个给一个命名术语，以及能把它和另外几个区分开的信号；再选最可能的一个展开术语，并说明为什么选它。

1. 给出 8 到 12 个专业术语，按“对最终造出来的东西改变多大”从高到低排序。每条包含：术语原文与一句白话释义、它对应用户描述里的哪一块、一个真实以该含义使用它的项目/论文/系统及链接、有了这个词能向 agent 提出什么具体要求。
2. 选 2 到 3 个用不同名称解决过同形问题的相邻领域。每个领域说明：哪些做法可以迁移、类比在哪里失效、哪些术语可以带回来用。
3. 点出用户没提、但这个问题必须关心的事。
4. 用这些新术语重写用户的描述。

每个链接必须实际打开核对，确认对方确实按这个含义使用该术语；无法核实的引用一律删掉。不要凑字和寒暄。

本次只交付以上内容和重写后的描述，不执行任务，不修改文件。收口点名下一步：需要不扩大范围继续改深、补齐完成条件与证据时运行 `/sharpen`，否则直接把重写后的描述交给 `/dimon-mode` 执行。
