# 例外模式：逐票合入

触发：用户在第 7 步看过本 MMF 的票数与拆分信号合计后，确认它切不开、又要逐票合入。此时逐票合入 main 换逐票的小合入，代价是隐藏手法与收尾片。

本文件叠加在 [SKILL.md](../SKILL.md) 之上：默认模式的词汇、检查、步骤与依赖边规则照常适用，下面只写增补。

## 增补词汇

- **收尾片**：删掉隐藏手法留下的第二条路径：toggle、旧 adapter、旧列。
- **完成**：合入 + 部署 + 至少内部可体验。flag 关着、只对内部账号开放也算完成；对外放量按里程碑记录，不阻塞下一片。
- **波次内单独合入**：同波次并发开发，每片完成即单独合入，不等同波次其他片，也不等里程碑。
- **里程碑**：story map 上的一条 release 切线。它的片全部完成后，打开这批片的 release toggle，让目标用户真正使用，并触发验收、结算等对外节点。里程碑只决定放量，不决定合入。_Avoid_：阶段合并、批量发布。

## 增补检查

删除测试的例外加上收尾片：它指向要删掉的路径。

5. **可独立部署**：单独合入 main 就能部署，现有行为保持不变。
6. **隐藏有期限**：用了 toggle、dark launch、branch by abstraction 或 expand-contract，就要有对应收尾片。release toggle 的收尾片紧跟所属里程碑的放量。被替换的是内部 Interface、没有外部调用方时，按运行时目录完整读取 `principle-migrate-callers-then-delete-legacy-apis/SKILL.md`，把迁移调用方和删除旧 Interface 放进同一波，不留中间态。
7. **small batch**：每片的拆分信号在 `ticket-split-100k` 拆分线以内，或带它写下的保留依据；每片完成即单独合入，不在分支上攒片。分支约两天内合回 main 是启发式，不是门槛。

## 增补步骤

- **第 4 步加隐藏手法。** 未完成部分合入时需要隐藏，按 [拆法库](splitting-patterns.md) 的隐藏手法表选手法，并补收尾片。完成条件：每个隐藏手法都有收尾片。
- **第 6 步后排里程碑。** 沿业务主线画 release 切线：
  - 里程碑 1 是骨架，加上让目标用户第一次能真正使用所需的最少加厚片。缺了会让流程不可用、或会造成资损与数据错误的规则，归进同一里程碑；没有刹车的车不发。
  - 之后每个里程碑只多交付一个对外可感知的业务结果，并配一个自己的 release toggle。
  - release toggle 只活到所属里程碑放量，随后由收尾片删除。toggle 存活一两周以内是启发式，不是门槛；预计更久时，向用户提出把这个里程碑切成两个对外结果。
  - 每个里程碑写明放量对象（灰度或全量的外部目标用户；内部体验已由每片的「完成」覆盖）、验收人与验收结果，以及目标项目约定的对外节点（演示、验收、结算或催款）。

  完成条件：每片有所属里程碑；每个里程碑都有放量对象、验收人和验收结果；不存在一个 toggle 一直覆盖到最后一片的计划。只排出一个里程碑时，写明理由。
- **第 7 步加列加表。** 切片表加「里程碑」「small batch 判断与依据」「隐藏手法 / 收尾片」三列，类型取值加「收尾」；再给里程碑表：

## 增补审查信号

小票合入后攒成一次大发布，或按「阶段」攒齐再一起合并；所有 toggle 留到最后一张票才打开或删除。多张票时另看波次与里程碑能否按「第 6 步后排里程碑」排出。

## 执行交接

切片发布后，按依赖并发执行与逐票上线交给 delivery-pipeline 的独立票模式（`delivery_mode: ticket_release`）。ready 只看本票阻塞边，每张票各走一个 MR，部署读回后关票。合入授权与部署读回按该模式的 `release_stage` 规则执行；它的状态止于 `deployed`。里程碑的放量与对外节点按里程碑表执行，可映射到 tracker 的 milestone。宿主没有 delivery-pipeline 时，按目标项目自己的分支与发布合同逐票合入。
