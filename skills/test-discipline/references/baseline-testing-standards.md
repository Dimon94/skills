# 测试规范

本规范归本项目所有。测试只保护已接受的需求、具体缺陷与当前受影响的不变量。

## 选择检查

1. **验收范围。** 先列出本次需要证明的可观察结果，再查已有检查。新增用例必须点名已有覆盖遗漏的具体风险；文件改动、覆盖率或假想需求不是理由。纯文档与低影响静态修改使用适用的静态检查。已有覆盖充分时直接复用。
2. **端到端。** 默认优先用 E2E 覆盖当前验收，不逐层补同义测试。E2E 指穿过真实公开入口：UI、API、CLI 或库的公开函数，观察完整功能的关键结果和真实失败边界。
3. **隔离例外。** 只有具体失败边界无法由 E2E 可靠触发或观察时，才增加隔离测试，先说明缺口。先列全该边界当前合同内已知的失败方式，写出会失败的用例，再写实现；目标行为未定时先确认合同，不穷举假想故障。E2E 环境阻塞仍须报告为验收缺口。

## 阶段相称

按项目 AGENTS.md 与 agent 记忆判断项目阶段。选择测试前逐条回答：

- 这项测试回答的问题，项目现在有证据需要回答吗？
- 规模、并发、数据量来自哪份已观测或已承诺的事实？
- 这个环境产出的结论能预测真实运行吗？
- 为它新增的设施，现在有人维护、有人看结果吗？

任一项答不上：不写这项测试，回到当前验收所需的最小检查。按二八原则，把测试留给主要业务价值与高影响风险。

## 断言与执行

- 断言公开结果、错误与不变量，并点名一个会让断言失败的错误实现。预期值来自合同、需求示例、手算或标准向量，不从被测实现反抄。
- 隔离测试在已有 seam 处替换外部依赖，不为测试扩大公开 API。Mock 自身设定不能证明真实集成。
- 使用可重置的隔离数据。付费服务、生产数据与不可逆副作用使用安全环境或 fixture。
- 只控制影响当前断言的时间、随机与并发，使结果可重复；并发优先确定性协调，无法消除的外部时序须说明不确定性。

## 证据产物

保留入口、输入或前置状态、预期与实际结果、复跑命令及报告路径。优先复用现有 runner 的报告、日志或截图；无 runner 时保存命令与结果即可，不为建档新增报告设施。截图或文件存在本身不证明通过。

内容差异用 diff，功能正确性用结果与状态读回。SHA256 等摘要校验只用于明确的完整性、安全或发布合同，并点名该合同；摘要一致不能证明业务正确性。

## 语言节

按各节标明的目录执行。Unknown 表示尚无证据，不据此安装依赖或编造命令。
