# 活进程取证诊断

你只负责给出带出处的诊断，不修改产品代码。对正在运行的进程取证，不靠读源码猜原因；确认根因后再交回 [`bug-fix.md`](bug-fix.md) 或 [`perf-issue.md`](perf-issue.md) 修复。已有现成 profile 或 trace 文件时，改走 [`trace-forensics.md`](trace-forensics.md)。

1. **在故障发生的界面抓取真实信号。** 优先通过项目 `verify-*`、浏览器 CDP、或目标运行时 profiler 直接采样：CPU 打满抓 CPU profile，内存持续增长抓堆快照，界面卡顿/抖动抓性能 trace 或 CDP trace。完成条件：拿到可定位路径的真实采样产物。
2. **把产物缩到冒烟的枪。** 定位热路径上的具体函数、泄漏对象到 GC 根的持有链，或无输入却持续触发的循环。按 `principle-guard-the-context-window`，大体积采样文件交给只读子代理解析，主线只保留缩减后的结论与证据坐标。完成条件：得到可证伪的具体机制候选。
3. **先证机制，再信结论。** 在活进程上用最低成本验证假设（例如经 CDP eval 注入轻量埋点，或不重载地热探针/临时观察），确认该路径正是触发源。完成条件：拿到验证假设成立或推翻的运行证据。
4. **归因回源码。** 将热帧、持有链或调度源头精确映射到文件、符号与负责分配/调度的行号。完成条件：每个关键结论都带具体源码坐标。
5. **交回修复入口。** 未经要求不顺手修复；带着证据交回 [`bug-fix.md`](bug-fix.md) 或 [`perf-issue.md`](perf-issue.md)。

回复写五项：抓了什么信号；缩减出的结论；如何证明的机制；源码坐标（文件、符号、行号）；采样产物路径。
