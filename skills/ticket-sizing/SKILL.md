# Ticket Sizing

为每张候选票估算 token 拆分信号，结合独立验收与依赖边界确定粒度。交付链内，本步的调用方是 `vertical-slicing`，发布仍交 `to-tickets`。
拆分信号只回答一个问题：这张票要不要再找一条独立验收边界切开。它只在拆票时使用，不写入票正文、派发 packet 或 lane 提示词，也不是执行预算。逐票表服务规划，留在规划侧；
执行按任务需要用量，执行 agent 的实际用量高于预测是常态，这个差记进“实测校准”列，用于修正后续预测。

## 执行步骤

1. 读取 Spec、候选票、依赖和相关代码，逐票明确验收目标、单个 Execution Worktree 的
   交付边界、需加载的代码与测试、验证路径和主要未知项。完成条件：每票均有具体范围与证据坐标。
2. 每张候选票必须主动给出 token 预测，按下节估算并填写逐票表；用户无需追加提醒。
   完成条件：每票都有数值区间、分项依据、假设和置信度，包括缺少历史运行数据的票。
3. 按粒度判据保留、拆分或合并；范围变化后重新估算最终票，合并票按共享上下文去重；再填 MMF 合计行。
   完成条件：最终每票均有预测、判定理由、独立验收与显式依赖；超过拆分线的票有拆分建议，
   或写明试过的边界与切不开的理由；每个 MMF 的合计行附推荐与理由。
4. 保存逐票表，交给调用方 `vertical-slicing`。展示、三选一与发布只按 `../vertical-slicing/SKILL.md`「切分 MMF」；本 skill 不发布。
   保存到执行 agent 读不到的位置：目标项目仓库之外，或目标项目约定的规划产物位置且不被任何票引用。票的标题和正文只写行为、验收、依赖与 prereq check。
   直接调用本 skill 时，最终回复展示逐票表，不能仅链接产物。
   完成条件：调用方在用户选定前能看到每票预测区间、拆分信号、主要不确定性、MMF 合计与推荐，以及保存路径。

## Token 预测

这里要求的是事前工程估算，统一标注“推断”，不是运行后的精确计量。
预测区间不能用 Unknown 代替；缺少证据时基于明确的范围假设给出更宽区间和低置信度，
列出待核验项。若范围尚未确定，给出条件式预测（“假设只覆盖 X，则为 L–U tokens”），
并将粒度结论标为待补充范围。

- **上下文峰值预测**：估算执行期间需同时保留的指令/规格、相关代码/测试、
  实现与调试对话/工具输出的 tokens；逐项给出数值区间和依据，按可能同时在场的阶段合计，
  共享内容计一次。依据来自预计读取范围、内容量、修改复杂度和验证/返工路径。
- **拆分信号**：在峰值上界之上加入明确数值的余量，说明余量对应的风险。拆分线由调用方给出
  （如 `ticket-split-100k`）。累计消耗不等于同时占用的上下文；用户另需费用或累计输入/输出消耗预测时，
  单列口径，拆票只看拆分信号。
- **校准与容量**：相近任务的实测记录用于修正预测；没有实测记录时，仅“实测校准”记 Unknown。
  当前模型/宿主的可用上下文容量有证据才填写，无证据记 Unknown，并将容量适配标为待核验；
  token 预测照常交付。容量已知时它是拆分判断的输入：拆分信号高于可用容量，就沿验收边界拆分
  或收窄读取与验证范围后重估。数值按证据精度取整，不套统一前后端系数或固定模型阈值。

逐票产物格式（可用同字段列表）：

| 票 | 验收目标 / 依赖 | 上下文峰值预测（tokens） | 拆分信号（tokens） | 分项依据 / 假设 / 置信度 | 实测校准 / 可用容量 | 保留、拆分或合并及理由 |
| --- | --- | --- | --- | --- | --- | --- |
| MMF 合计 | MMF 名称 · 票数 | | 拆分信号合计 | | | 推荐及理由 |

每个 MMF 一行合计。MMF 的定义见 `../../GLOSSARY.md` 的 MMF 词条。合计是重切信号：本 skill 给推荐与理由，用户裁决，合计不设阈值。

## 委派评估

`vertical-slicing` 可将逐票评估委派给只读子代理，传入本 skill 绝对路径、Spec、候选票与依赖、
相关代码证据；子代理按上述逐票产物格式返回完整评估。调用方核验并保存产物。
发布仍交 `to-tickets`。评估必做，委派可选；模型与并发按宿主合同核验。

## 判据

每张 ticket 应有一个可检查的交付目标，能在单个 Execution Worktree 内实现、验证与交回；
所需前置产物明确为 dependency，不把跨票协同留成隐含条件。普通文件路径重叠本身不是拆票理由。
依赖的是上游提供的**能力**（接口、服务、配置）而不只是产物时，在票内声明可执行 prereq check
（命令/探测 + 期望证据，ADR-0011）；能力是否就绪由该检查在运行中验成事实，不由计划文字担保。

- **拆分：** 包含可独立验收的多个目标，或读取、实现和验证所需的同时在场上下文无法可靠承载时，
  沿交付物或依赖边界拆分，保留明确的验收与集成顺序。
- **合并：** 相邻细票没有独立验收价值、反复加载同一上下文且能在同一 Execution Worktree
  验证时合并；保留真实 dependency，已派发或被 claim 的票不由本 skill 自动重写。
