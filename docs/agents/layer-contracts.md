# L1-L6 Contract Layers

用途：把下次修改必须知道的事实放在最近代码坐标。只写会约束实现、验证或排障的内容。

## 1. 层级

L1 项目宪法：系统为何存在、目标函数、不可破坏的不变量和顶层依赖。

L2 模块地图：模块职责、公开入口、成员、依赖、反模式和测试锚点。

L3 文件合同：文件依赖、输出、模块位置和测试坐标。

L4 关键函数合同：输入前提、输出承诺、不变量、失败语义和测试。Skill 里允许执行的脚本（如 repo://skills/postmortem/scripts/postmortem-contract.js）按 L4 对待。

L5 参数合同：名称、来源、单位、范围、默认值、配对约束和错误影响。

L6 过程合同：阶段顺序、fallback、状态读写、恢复、幂等、取消和并发分支。

L1-L6 逐层披露，不互相镜像。每条规范性陈述只有一个 canonical owner。其他层只写本层需要的派生约束，并用 repo:// 指回 owner。

## 2. 查看触发

改以下内容前先读本文件：

- 项目目标、顶层模块、跨模块依赖和外部系统。
- 模块职责、公开入口、成员和测试锚点。
- 核心文件、共享状态和跨模块边界。
- 公开导出、adapter、gateway、持久读写和状态迁移。
- CLI/API、payload、schema、env 和 config。
- 重试、恢复、取消、并发、fallback、成本、配额和 timeout。
- 曾经发生事故的流程分支。

## 3. 更新规则

更新 L1：

- 项目目标或全局不变量变化。
- 顶层模块、依赖方向或外部系统合同变化。
- 根级公开合同的含义变化。

更新 L2：

- 模块职责、成员、公开入口或依赖变化。
- 文件新增、删除或移动。
- 模块测试入口变化。

更新 L3：

- 核心文件职责、依赖、导出或测试锚点变化。

更新 L4：

- 公开导出、外部 seam、状态写入、幂等、重试、恢复、取消、并发或复杂规则变化。

更新 L5：

- API/CLI、payload、schema、env/config、成本、并发、重试、配额或 timeout 参数变化。

更新 L6：

- 阶段顺序、fallback、状态读写顺序、恢复、取消、并发或历史事故分支变化。

不更新：

- 局部变量。
- 普通短函数。
- 测试内部 helper。
- 纯格式化和拼写。
- 无合同含义的文案。

## 4. 回环完成条件

1. 列出当前变更命中的实际触发面。
2. 更新每个命中层。Not applicable 时记录一行理由。
3. 核对合同反映当前代码或运行事实。
4. 每条新增规范可以追溯到代码、测试、运行证据、外部合同或 accepted ADR。
5. 移动或删除文件后，最近 L2 不保留旧路径。

## 5. 模板

L1：

    目标: 系统存在理由和当前目标函数
    链路: 端到端数据或操作链路
    不变量: 任何实现不能破坏的根约束
    模块: 顶层模块和依赖方向
    依赖: 外部系统和运行环境
    外部合同: CLI/API/schema/跨系统合同
    验证: 根级检查入口
    PROTOCOL: 根合同变化时同步哪些坐标

L2：

    模块职责: 本模块拥有和不拥有的职责
    成员清单: 关键目录、文件和公开入口
    生成规则: build output 和 ignored 文件
    反模式: 本模块禁止的实现
    测试锚点: 最小验证入口

本仓模块是 skill。skill 的 L2 由它的 SKILL.md 正文承担，不为 skill 建独立模块地图。

L3：

    COORD: 仓库相对路径
    INPUT: 依赖和上游真相
    OUTPUT: 导出、写入和外部合同
    POS: 模块位置和不承担的职责
    TEST: 最小证明
    PROTOCOL: 变更时同步的坐标

L4：

    IN: 输入前提和 caller 责任
    OUT: 返回或写入承诺
    INVARIANT: 必须保持的不变量
    FAIL: 失败语义和恢复动作
    TEST: 覆盖合同的测试

L5：

    PARAM: 名称、中文语义、来源、单位、范围、默认值
    PAIR: 与其他参数或字段的配对约束
    FAIL: 错误值造成的失败
    TEST: 锁定参数的测试

L6：

    DOC: 依赖的 ADR、runbook 或外部合同
    WHY: 顺序存在的原因
    CHAIN: 阶段、fallback、状态读写和迁移
    TEXT: 不可随意改变的用户或操作员文案
    FAIL: 历史失败和错误分支影响
    TEST: 最小回归证明

## 6. 写作原则

- 好合同写不变量和边界。
- 坏合同逐句翻译代码。
- 能由测试锁定时，写测试坐标。
- 来自其他文档时，用 repo:// 指向 canonical owner。
- 合同越靠近代码越短。
- 不确定时写 Unknown。
- 地图必须帮助下一次正确定位、修改或验证。
