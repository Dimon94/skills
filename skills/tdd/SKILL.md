# TDD

TDD 是 red → green 循环。本 Skill 决定每条验收要不要循环、在哪层循环，以及怎样证明留下的检查有价值。

开工前读目标项目的测试规范：首选根 `AGENTS.md` 中以 `测试规范：` 开头的索引行，其次是 `docs/agents/quality-standards.md`、`TESTING.md`、`CONTRIBUTING.md`。项目规范与本 Skill 冲突时，项目规范优先。测试名和断言用词沿用项目的 `GLOSSARY.md` 或 `CONTEXT.md`。

## 1. 分流

按改动类型选择路径：

| 改动 | 路径 |
| --- | --- |
| 没有可观察的行为变化：改名、零调用删除、文档、格式 | 不新写测试。跑现有最近测试与静态检查，作为基线和结果 |
| 缺陷 | 用同一输入先复现，复现就是 red |
| 行为已定的功能 | 每条验收走一次第 3–5 步 |
| 行为未定 | 先确认合同，再写检查。对未定行为写的测试会钉住错误行为 |
| 并发、重试、幂等、状态机、资金或去重承诺 | 照常走红绿，另按第 2 步判断要不要形式验证 |

不写测试的改动，在提交说明写一行理由和已跑的检查。

完成条件：每条验收都有路径；不写测试的理由可读。

## 2. 独立预期与选层

**独立预期**是期望值的来历：不看实现也能写出的值。每条验收要有三项：输入或动作、期望结果、来源。

- 合格来源：用户确认的例子、spec 原文、外部标准或真实系统响应、历史缺陷的复现输入、手算结果；纯重构可用旧版本行为。
- 不合格来源：跑当前实现得到的值、从实现复制的常量或映射、同一模型的第二次判断。

验收缺独立预期时，从 spec 或计划补齐；指不出来源就停下来问，不写这条检查。`implement` 列出的失败方式同样是验收，同样走这一步。

层按缺陷藏在哪里选，依次问三个问题：

1. 缺陷在单个 owner 内部，还是跨 owner 的接线？前者往下放，后者往上放。
2. 这一层能真实触发并观察到结果吗？不能就换层。
3. 组合有多少？组合多的下沉到最快的公开 seam 穷举，上层只留一条代表路径。

| 情况 | 层 |
| --- | --- |
| 组件合同、持久化、权限、IPC、真实宿主 | E2E 或合同检查，并读回结果 |
| 规则、金额、分支组合 | 最快的公开 seam 穷举，加 1 条 E2E 验接线 |
| 没有 seam 的遗留代码 | 先用 E2E 兜底，再重构 |
| 并发、重试、幂等的时序交错 | 项目已有的 `formal-verify-<area>`，加 1 条 E2E |
| 形状错误 | 类型检查 |
| 性能、使用性 | 基准或人工评估，不走红绿 |

seam 优先用 spec 指定的；没有指定时选最高的现有公开入口，并在交付说明里写明选了哪个。测试穿过公开入口，不为测试扩大公开 API。替身只放在外部系统边界：第三方服务、时间、随机。

完成条件：每条要写的检查都有独立预期和层。

## 3. Red

一次只写一条检查，按 vertical slice 推进：一条检查、一份最小实现，再下一条。先写全部测试再写实现，会钉住想象中的行为。

运行新检查，确认它失败，且失败原因正是目标行为缺失。环境、拼写或导入错误造成的失败先修好再判定。断言公开结果、错误、读回的状态或外部副作用；“不该发生”的合同同时断言副作用没有发生，例如报错后没有保存。

完成条件：有一份 red 运行记录，失败信息指向目标行为。

## 4. Green

写让检查通过的最小实现。Green 阶段检查只读：要改期望值，先回到它的来源写明原因；判断不了就上报，不改断言去迁就实现。重构不在这个循环里，留给审查阶段。

完成条件：同一检查 green，原有相关检查仍通过。

## 5. 探针

探针要真跑。设想中的错误实现不算证据。

1. **空返回探针**：red 是在目标行为缺失时跑出来的，就算已经过了这一关。给已有行为补的检查没有 red，要单独跑：把被测入口改成返回空值或默认值、不产生副作用，检查必须因具体断言失败。
2. **近似错误**：每条新增检查再跑 1 个按验收推出的近似错误实现，例如差一、分支条件错、跳过副作用、副作用重复。不用重新构建的层必跑；要重新构建的层只在金额、权限、持久数据或数据丢失相关的验收上跑。

操作在当前工作树：把被测文件复制到仓库外的临时目录，改错，跑目标检查，复制回来，用 `cmp` 确认与备份字节一致，再跑一次 green。字节不一致就停下报告，不继续。

近似错误仍通过时，按独立预期收紧断言，再跑一次探针。探针只证明检查敏感；期望值对不对，由第 2 步的来源保证。判断测试价值的细则见 [测试启发式](../test-review/references/test-heuristics.md)。

完成条件：每条新增检查都有 red、green 与探针三份运行记录，写进交付说明或提交说明。
