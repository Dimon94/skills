# Development Workflow

用途：约束功能开发、缺陷修复、重构和交付。主词是证据闭环。

## 1. 定义目标

记录用户现象、可观察结果、范围和不变量。

动手前向用户复述：真正想要什么、本次范围、非目标、怎样算完成。执行前产出最小计划，写清目标、非目标、验收标准和不改动的范围。

- 根因未知时，保持方案中立。
- 验收标准只写外部可观察结果和必须保持的合同。
- 实现猜想放入调查记录，不写成需求。
- 变更边界由请求定义。只改请求点名的面；边界外发现的问题报告给用户，不顺手修进同一 diff。独立观察便宜，纠缠的 diff 贵。
- 歧义只在答案会实质改变结果、范围、风险或授权时才提问；其余陈述假设并继续。
- 多条可行路径存在实质取舍时，给出唯一推荐和理由；备选只在对结论有实质影响时列出。

完成标准：任务可独立验证；未知项明确标为 Unknown。

## 2. 锁定基线

读取目标文件最近的 AGENTS.md、CONTEXT.md、System Map、直接调用者、公开入口、相关测试和配置。

记录：

- 当前分支和工作区状态。
- 最小现有测试的结果。
- 相关运行证据或复现输入。
- 用户已有的无关修改。
- 支撑结论的证据坐标：仓库结论来自实际检查的代码、测试、配置、当前状态和历史，关键处引用确切证据；第三方行为以匹配项目版本的官方一手文档为准，升级或全新选型用最新官方指南；来源冲突时点名。

完成标准：知道哪项现有行为将作为对照，且不会覆盖无关改动。

## 3. 设计最小切片

按 repo://docs/agents/coding-standards.md 第 2 节的复用顺序与搜索键寻找实现。

用户要求更广设计时，不以首个例子或即时负载过度拟合。

若改变所有权、依赖方向、公开合同或持久状态，先读 Architecture Standards 和 Layer Contracts。难回退决定先写 ADR。

完成标准：每个新增实体都有当前职责；不存在平行机制。

## 4. 留下失败检查

功能开发先写能区分完成与未完成的检查。缺陷修复用同一输入复现问题。目标行为仍在讨论时，先锁定逻辑再写检查：对未定行为写的测试会钉住错误行为，并反过来为它辩护。

优先级：

1. 最近 public interface 的 focused test。
2. 边界 adapter 的合同测试。
3. 最小可复跑的 assert 或命令。
4. 关键真实路径的 smoke test。

完成标准：错误实现会失败；检查不依赖私有实现细节。

## 5. 实现

修改 canonical owner。保持 adapter 薄。把副作用集中到明确写入者。

- 输入在 seam 校验。
- 内部使用 typed value。
- 失败语义稳定且可测试。
- 并发、重试、幂等和恢复由 owner 表达。
- 不添加当前需求之外的配置、fallback 或扩展点。
- 变更落到它蕴含的每个站点。宣告完成前 grep 所改对象的同类：同类型卡片、同 key 文案、同 helper 的调用方，确认每个都已改或正确地未改。
- 匹配同类是请求的一部分：既有种类的新成员继承该种类的必填字段、命名约定和文案约定，无需逐一被告知。
- 用户纠正某条判定标准时，把纠正后的标准应用到相关范围的全部同类，不只改被点名的例子。

完成标准：最小检查通过，原有边界保持成立。

## 6. 验证

按风险逐层运行：

1. focused test。
2. 受影响模块测试。
3. 类型检查、lint 或语法检查。
4. build。
5. 必要时走真实公开入口。

真实入口同时断言 transport 和业务结果（repo://docs/agents/coding-standards.md 第 6 节）。

完成标准：验证命令可复跑；结果与需求和不变量一致。

## 7. 文档回环

按 Layer Contracts 列出当前变更命中的 L1-L6 触发面。更新对应 canonical 文档。

- 统一语言变化：CONTEXT.md。
- 顶层所有权或依赖变化：System Map。
- 难回退决定：ADR。
- 模块成员或入口变化：最近 AGENTS.md。
- 公开参数和流程约束：最近代码合同或专用合同文档。
- 用户可见行为或文案变化：按 repo://docs/agents/writing-standards.md 第 7 节清扫文案面，并修复改名和移动造成的断链。

完成标准：文档描述当前事实，不描述尚未落地的愿景。

## 8. 收口

运行 git diff --check，并检查工作区。对照最小计划核对：非目标与不改动范围未被触及，diff 只含计划内文件，无残留调试代码。

长任务保持全局计划和最终目标，只汇报实质进展。

交付说明包含：

- 触达坐标。
- 实际改动。
- 验证命令和结果。
- 跳过项与剩余风险。
- 本次写入 repo://docs/deferred-hardening.md 的新增或变更条目；无新发现时点名“无新增”。
- schema、公开 API 和兼容性面的变化显式点名；用户可见的 CLI 变化粘贴真实终端输出。
- 需要用户输入或决策的事项。

审查、审计、解释、报告、计划和提案均为只读交付物，不授权实现。只有用户明确要求，或当前任务中已明确确立工作流时，才 stage、commit、push、修改或合并 PR、发布或部署。Stage 时列出具体路径。提交被要求时，每个提交保持语义内聚、可独立审查并排除无关改动；交付说明列出 commit hash 和已执行的验证。
