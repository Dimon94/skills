# 对标参考产品

用户点名一个参考产品（“学习 X”“对比 X 的代码”“像 X 一样”），它的做法就是期望来源。先读它，再设计。

1. 找源码。先在本机找参考产品的 clone：项目 AGENTS.md 的指针、用户给过的路径、本机源码库目录。找到就用，不问用户要；找不到才说明找过哪里，再问。
2. 走通对应链路。用 `how` 在参考源码里追同一个用户动作：入口、状态、数据形状、时序、缓存与预加载、失败处理。记下文件坐标。
3. 列差异。逐项对照本项目的同一条链路，分成三栏：照搬、因本项目约束要适配（写明约束）、不做（写明理由）。用户说“一比一复刻”时，“不做”栏每一项都要用户认可。
4. 实现差异，不重写已对齐的部分。是缺陷就按 `playbooks/bug-fix.md` 修。
5. 在同一界面上并排验收：同一个用户动作，在参考产品和本项目里各跑一遍，对比可见行为和耗时。只读了源码没跑，就写 Unknown。

回复写：参考产品怎么做的（附源码坐标）；本项目差在哪；照搬了什么、适配了什么；并排验收结果。
