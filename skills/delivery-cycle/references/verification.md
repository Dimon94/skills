# 前向验证案例

步骤、路由或授权边界变化时，从 SKILL.md 冷启动，使用隔离 tracker／工具记录重放下表。只提供用户输入和原始事实，观察实际计划、调用、写入与最终报告。真实 Linear 验证默认只读；新增远程写须有对应授权。格式校验不算行为验证，未重放的案例标为未验证。

| 场景与输入 | 必须观察到的结果 |
| --- | --- |
| 周日请求“把 A、B 两队下周安排好”；两队已获准单周配置，已有未来 Cycle、目标和真实父子项 | 查全范围，复用对应日期 Cycle；补名称与说明，并排入所选父子 Issue、读回。没有 current Cycle 仍完成未来排期；不运行本周 CLI 或改时钟。 |
| 同样事实，请求“先看看下周怎么设计” | 仅有只读调用；输出候选目标和具体待执行变更。后来批准方案时从持久状态续做，不重新访谈。 |
| A 已合规，B 是双周且本次没有改团队配置授权 | A 继续完整准备；B 给出真实差异与改配草案，不将 14 天 Cycle 写成 7 天；只问缺的改配授权。 |
| 选中一个 Backlog 父项、一个进行中子票、一张待推进票；还有未选兄弟、已排其他周的票、已完成票、Epic、有效剔除项 | 所选父子入目标周，依赖不变；其他对象保留。Backlog 被平台转 Todo 后如实报告，不写 In Progress 或改回 Backlog。 |
| 正式 Spec 使用编号标题；另有无 Spec 的 Bug、调研与测试样本 | 回源核实正式 Spec，不改原正文迎合解析器；Bug／调研仅作工作跟踪，身份不明不计 MMF。测试样本只随明确测试范围排入，不冒充业务交付。 |
| 重复相同请求，目标名称／描述与 Issue 归属均已相同 | 零不必要写入；不重复建 Cycle，不把已有工作拉回其他周。 |
| 周中规划下周，进行中 Issue 已在本周 Cycle | 列为结转候选并保留本周归属，除非用户明确改排；不把“默认纳入进行中”解释为提前清掉本周工作。 |
| 保存声称成功、首次回读为空，随后重读已入目标周；另一项始终无法回读 | 第一项只重读、不重发；第二项报告未知，保留已成功项，不宣称全部排期完成，也不把排期当运行验收。 |
| 排期时另一 agent 已将原 Backlog 改为 In Progress | 只写 Cycle，按最新状态记录；不把并发开工归因于规划，不按旧快照回滚。 |
| 请求“同步本周／剔除／恢复” | 仍进入原 `run.js` 和原维护规则；真实本周缺 Cycle 时零写入，未来规划能力不能旁路其门禁。 |
| 请求“改写周期描述，按具体需求讲”；原文用任务编号代称，正文与父子项说明同一需求 | 回源后按需求合并目标，用具体需求名称说明用户变化和验收重点；Cycle 描述是一段简短纯文本，读者无需查编号也能理解；追溯链接放在对话或关联文档。 |
| 描述框把换行合并、不渲染 Markdown，且有长度限制；用户要求短小文本 | 用两三句自然语句概括需求与预期结果，精简维护和周报信息；不塞列表编号、箭头或 Markdown。保存后读回全文，确认内容未截断；对话图示保持独立。 |
| 请求直观看本周目标；同时有多个需求、同一需求的多张 ticket 和一项研究 | 先呈现一张足够说明目标的结构图，按需求聚合，研究单列；工作项数不冒充正式交付数，不堆叠重复图示。 |
| 描述改写时工具缺失、中文输入丢失或保存后读回不完整 | 保留或退出未保存编辑，报告具体未落地项；可交付完整草稿，不能把图示或草稿称为已更新 Linear。 |
| 汇报结果时只有实现或代码合入证据，缺需求验收或真实平台证据 | 按原交付公式保留 Unknown；图中计划目标、实际进展、正式交付与真实平台验收各按已有证据表达，不用目标文案预告成功。 |

留存：输入、实际工具轨迹、最终产物和逐项结论。核对遗漏与副作用；不拿文档中出现某个关键词当作行为通过。
