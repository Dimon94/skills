# 前向验证案例

给独立会话 SKILL.md 路径与下列输入，不给预期答案；按检查项判定实际输出。没有 tracker 与发布授权，输出应是未发布的切片清单。

## 共用输入：优惠券 spec

电商项目新增优惠券。验收标准：

1. 运营在后台创建满减券：面额、门槛、有效期、总量。
2. 用户在商品详情页领券，每人限领一张。
3. 下单时自动选中可用的最优券，订单金额扣减。
4. 退款时按比例退回已用券的抵扣。
5. 券过期后不可用，用户券包标灰。
6. 运营查看每张券的领取与核销报表。

代码事实：订单金额由 `OrderPricing` Module 计算，Interface 为 `price(cart) -> Quote`；用户中心与商品详情页已上线；无券相关表；项目有 feature flag 服务。

## 主路径：切分

检查：

- 第一片是 walking skeleton，只覆盖核心闭环（创建、领取、下单抵扣）：一张硬编码或后台最简创建的券，用户能领取，下单时能看到抵扣。一片只建表、只做 API 或只做后台页面，均失败；骨架同时装入退款或报表，也失败。
- 退款、报表各自成片；每片给出 small batch 判断与依据。
- `OrderPricing` 的 Interface 变动落在骨架或其前置结构片里；加厚片只在 seam 后补变体。
- 每条阻塞边写明依赖的 Interface 或能力；至少两张加厚片之间没有阻塞边，可以并发。
- 用户可见部分有隐藏手法，并有对应收尾片。
- 六条验收标准都落到某一片，或列入延后、丢弃并写理由；不存在「联调」「集成」「上线」票。
- 每片的体验结果都写成「谁 · 入口 · 做什么 · 看到什么」。
- 每片有波次号与所属里程碑；至少两个里程碑。里程碑 1 含骨架与防资损规则（每人限领、总量），早于最后一片放量；报表落在后续里程碑。退款放进哪个里程碑都可以，但要写出资损理由。
- 每个里程碑有放量对象、验收人与验收结果，以及自己的 release toggle 收尾片；单一 toggle 覆盖到最后一片即失败。

## 关键失败路径：审查横切拆票

输入同上，另给一份既有拆票：① 建 coupon 与 user_coupon 表 ② 券 CRUD API ③ 后台券管理页面 ④ 领券接口 ⑤ 前端领券与券包 ⑥ 订单接入优惠券 ⑦ 退款逻辑 ⑧ 报表 ⑨ 全链路联调与上线。

检查：

- 逐票报出未过的切片检查项，至少点名 ①②③ 无体验结果、⑨ 是集成票兼一次性大发布。
- 指出缺少端到端骨架，给出以骨架为第一片的重切方案；方案含切片表与里程碑表，六条验收标准都有落点。
- 里程碑 1 的放量对象是外部目标用户，并含每人限领与总量；只放内部账号的里程碑 1 失败。
- 每条 finding 指向票号与检查项。

同一检查先用于修改前的输出，再用于修改后的输出。通过只说明这两条路径的形状正确，不证明真实项目里的尺寸判断与依赖准确。
