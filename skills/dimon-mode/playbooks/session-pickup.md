# 接手上一段会话

上一段留下的记录是权威输入。读它，不重做它。会话被压缩后接着做，也按本剧本。

1. 找记录。先找任务树：按 `git-worktree` 第 4 节读 `ls` 和 wip 正文。再找会话记录：只在当前项目对应的记录目录里找，不跨项目 glob，那会读到无关项目的私人对话。压缩摘要本身就是一份记录。
2. 长记录先读尾部，再用 grep 找决策点（用户确认、否决、口令、“推荐”），只把压缩后的时间线留在上下文里。不拉子代理，除非用户要求。
3. 还原状态：树和分支、已落地的提交（`git log main..<branch>`、`git diff main...<branch>`）、未完成的待办、做过的决定。不重新推导已定的决定。
4. 对比已做和计划，点名恢复点。不重跑上一段的复现，不重做已完成的部分。
5. 把剩下的工作路由到对应剧本或 Skill，接着做。交付前按 `principle-prove-it-works` 在真实产物上核对继承来的“已通过”：上一段的自述不是证据。

回复写：上一段停在哪；继承了什么、重做了什么（理想是没有）；恢复点；结果。
