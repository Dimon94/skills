# Writing Standards

用途：约束用户可见文本与长效文档。覆盖 CLI 与诊断输出、错误信息、README 与 docs、生成的报告与导出。代码内注释归 repo://docs/agents/coding-standards.md 第 8 节；文案测试技术归 repo://docs/agents/quality-standards.md 第 6 节。

## 1. 第一原则

用户可见文本是产品行为，与代码适用同一质量门槛。每条文本以首次遇到该问题的读者为对象。会话回复（对话内即时输出）的样式归 repo://AGENTS.md <response_style>，本文件不约束。

## 2. 状态与诊断输出

- 状态输出报告生效值，不报告存储值。按运行时同样的顺序解析环境变量和分层配置。
- 配置层加载失败时，诊断回退到仍可加载的最完整状态，不回退到空白默认。误报的诊断比中止的诊断更糟。
- 健康检查只列出偏离默认的项及其来源；全量清单归专用 inspect 命令。一个命令不重复另一个命令的职责。
- 标注粒度与声明粒度一致。复合值中只有单个子项来源不同时，只标注该子项，不重标整体。
- 新增元数据后重读相邻标签，防止后缀与既有值标签撞名。
- 机器可读输出（porcelain/TSV/JSON）是合同：不加装饰、通知或注解；信息文本走 stderr 或人类格式路径。缺失也是合同，为必须不存在的内容写负向测试。
- 诊断中的路径、ID 和 URL 永不截断：窄终端下这些行禁用自动换行和裁剪。被截断的路径无法复制进下一条命令。

## 3. 错误信息

- 每条错误回答三个问题：发生了什么、在哪里、现在怎么办。
- 最强形态：点名违规文件或输入，列出被拒字段和允许字段，指出被拒设置应归属的位置。
- 错误语义、捕获与 fail-close 归 repo://docs/agents/coding-standards.md 第 6 节。

## 4. 文档归属

- 每个文档只承担一种职责：持久合同、提案、调查记录、TODO、有日期工单或 runbook。先命名职责；职责决定每个事实住在哪页，其他页面用一个具体链接到达。
- 两个页面都自称详细规范时，职责较宽的保留共享规则，较窄的只保留自己表面新增的内容。
- 设计理由归 ADR、设计记录或作出决定的 PR，不归使用文档。使用文档里的论证把步骤压到折叠线之下，且随实现迁移最先腐烂。
- 复述后附"详见 X"是缺陷：复述即全文。删除复述，保留链接和本表面特有的内容。
- 修订用最小充分编辑：保留未受影响的措辞、结构和理由；不重写相邻段落，不无理由压缩有效区分。
- 插入新节前检查相邻段落的依附对象，不拆散既有组合（如表格与其脚注）。
- "推荐""更快""更好"来自本仓评测或基准，不来自乐观。
- 页面按读者需要的顺序组织：范围与权威入口、常用规则与主路径、例外与恢复。概述层只写稳定语义并向下链接，不为自洽搬运字段表和当前数值。
- 一页开始要求读者理解多个无关任务时拆分。拆分后留下一行职责加链接，不留第二份事实。
- 提醒只点名最容易忘的一项；罗列全部产物的提醒会被整体跳过。

## 5. 会过期的事实

长效页面（README、架构、runbook、领域文档）只写稳定内容：意图、不变量、边界、流程、失败处理。

- 不手写移动速度快于文档的值：版本号、协议号、镜像 tag、build ID、已部署 commit、对象或迁移计数、过期日期、"当前已上线/未发布"声明。这些归 changelog、git history 或发布工单。
- 页面必须展示当前值时，从权威源在构建时生成，不维护手抄副本。
- 指针落到具体文件加可搜索符号（函数、数据键、标题）。"见源码"、仓根链接和裸目录不算指针。没有单一符号拥有该事实是代码边界问题，不靠复制表格掩盖。
- 目录只在两种情况是指针的合法目标：事实来自有序集合（如按序重放的迁移），或目录被加载器枚举（locales、插件）。两种都仍要给出可搜索的选择键：命名约定、加载器函数或对象名。
- 文档无法观测运行时。文档记录查询命令或控制台位置，不记录查询结果。merged 不等于 deployed。部署证据归发布工单，不转入长效文档。

## 6. 最终态，而非路径

交付物的读者不在制作现场。每行接受检验：未见过制作过程的读者是否仍成立。

- 标题、摘要和交付物只描述已交付行为。中间尝试、被放弃方案和否定式范围归 git history 和评审讨论。
- 生成的报告、演示和导出是产品内容：只承载结论、数值和指令。"本页演示""我们也可以""实现方式为"是生产者声音泄漏；实现笔记、方法理由和生产者的下一步归回复、commit message、PR 描述或计划文件。
- 需要读者行动的声明给出依据；只陈述行为的声明不附引用、基准数字或共识诉求。检验：删掉该行是否改变读者能做的决定。

## 7. 行为变更的文案清扫

行为变化在以下文案面全部同步后才算完成。按易忘顺序 grep 旧措辞：

1. `--help` 选项说明。
2. 集中消息/字符串模块与命令 docstring。
3. README 与 docs。
4. bundled skill 文件、插件元数据、MCP 工具描述。
5. 描述旧行为的 roadmap 或状态笔记。

随后重解析受影响的链接：改名的标题会断所有指向它的锚点，移动的文件会断指向它的相对路径。两者都不会在常规测试中暴露。
