# 超 100k 拆票

100k 是拆票启发式，只决定候选票要不要再拆。实际开发按任务需要用量，单张票不设上限。

执行 Agent 没有拆票上下文。Issue 只写行为、验收和依赖，它才不会把估算当成开发限额。

## 步骤

1. 读取最新逐票表。缺少执行预算的票，按 `ticket-sizing` 口径补上预测。
   完成条件：每张候选票都有上下文峰值和执行预算。
2. 划线。预算超过 100k 的票进入拆分；正好 100k 的票保留，并标为贴线。
   完成条件：每张票都标了拆分、保留或贴线。
3. 沿独立验收边界拆分。预备重构单独成票并排在前面。
   常用边界：探针与界面、服务端与客户端、schema 与入口、迁移与核验、包本体与接线、视图与页面。
   完成条件：每张新票有一个可独立检查的交付结果，依赖都写成显式阻断。
4. 重估每张新票。按拆分后的真实范围重算分项和余量，数字如实反映风险；仍超过 100k 就回到第 3 步。
   完成条件：所有票预算不超过 100k，贴线的票已点名。
5. 向用户展示新候选票和拆分对应表，数字存到本地产物。批准和发布归 `to-tickets`。
   完成条件：用户能看到每张票的预测，以及每张原票拆成了哪些新票。
6. 发布前逐票扫描 Issue 标题和正文，正文只留行为、验收、依赖和 prereq check。
   完成条件：`token`、`预算`、`上下文峰值`、`100k` 和具体估算数字在全部 Issue 里零命中。

## 例子

| 原票 | 原预算 | 拆成 | 新预算 |
| --- | ---: | --- | ---: |
| Codex 新会话读目录 | 145k | 目录可查询、选择器读目录 | 95k、100k |
| Claude 新会话读目录 | 155k | 启动环境收口、目录可查询、选择器读目录 | 85k、90k、95k |
| 预热与刷新 | 110k | 预热与手动刷新、事件刷新 | 80k、85k |
