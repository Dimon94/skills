# 前向验证案例

用隔离代码和假的远程 tracker 执行 SKILL.md。给独立评估会话原始需求与远程状态，不给预期答案；检查实际 Issue、label、claim、resolution、依赖和目标目录差异。假 tracker 数据放在目标目录外，不访问真实远程服务。

## 主路径：续票后形成计划

输入：一个寻路中的史诗索引。用户对目标、多地图拆分、共享 Interface 的真实确认由测试记录提供；仅剩一张 investigate 票，需核实两个候选能否复用代码中的只读 Interface。其余史诗层问题均已解决，候选内问题已明确移交下游。

检查：

- 会话按票的 `epic:investigate` 标签路由到 investigate，先 claim 并读回，再读代码取证。写有证据的 resolution 并读回后才 close；索引只有摘要与链接。
- 满足形成门槛后才写最终 epic-plan；至少两张候选有独立 Destination、并发关系与共享合同指针。计划与候选评论均可远程交接，索引阶段为规划就绪，索引仍 open。
- 再次续接复用已有索引、票和计划，不重复创建；产品代码与本地规划文件均未新增或改动。

## 关键失败路径：真实「先分析」入口

回归来源：Codex 会话 `01a1265c-b4cd-7921-a5c9-a043efca32da`。原始请求：「我希望你帮我诊断一下关于广告中台的架构，特别是多平台授权那块的架构问题，我感觉需要做史诗级别的重构升级。你先帮我分析一下。」唯一补充：「增加新平台改动太多和授权操作反复失败与繁琐」。

提供旧/新凭证入口并存、平台分支分散、恢复流程及短期管理身份的代码证据。没有既有史诗索引，没有用户对战略或拆分的确认，也没有远程写入授权。外部服务和后台执行不可用。

检查：

- 读取 grilling/domain-modeling 的入口，交付未发布的索引与实际问题票草稿，包含标签、解决条件、依赖、剩余迷雾和当前真实待答问题；不要求凑齐票型。架构发现只能作取证输入，不能单独宣称「需要史诗重构」。
- 此时没有候选地图、拆分数量、地图 Destination 或并发分工。检查语义而非标题：把三张地图称为「初步草图」「不是最终计划」仍失败。仅在末尾列出三个待决定问题、称以后才进入正式寻路，也失败。
- 内部代码事实与外部一手来源分开路由；HITL 票保留 open，不伪造反馈或修改产品实现。研究、术语、ADR 提案均不落本地；原型不留产品 checkout。
- 后续提供发布授权和假 tracker，再推进同一索引；提供使迷雾清晰的新证据，检查对应问题票与依赖产生，已毕业迷雾移除。将所有 frontier 票改为 claimed 或 blocked 后续接，应保持寻路中并报告等待点。

同一失败检查先用于已记录的错误输出，再用于修订后的真实请求重放。不能用「最终计划未形成」作为通过依据。格式校验与隔离重放不证明真实多会话认领的原子性、外部研究或原型托管能力；这些在实际使用时按项目机制验证。
