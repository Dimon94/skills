# 超 100k 拆票

100k 是拆分线：一张票的拆分信号超过它，就去找一条独立验收边界切开。数字只提示去找缝，票的边界以能独立检查为准。实际开发按任务需要用量。

拆分信号只服务规划，留在规划侧。票正文只写行为、验收、依赖和 prereq check。

## 步骤

1. 读取 `ticket-sizing` 最新逐票表的“拆分信号（tokens）”列。缺少拆分信号的票，按 `ticket-sizing` 口径补上。
   完成条件：每张候选票都有上下文峰值和拆分信号。
2. 划线。拆分信号超过拆分线的票标为待拆，其余保留。
   完成条件：每张票都标了待拆或保留。
3. 沿独立验收边界拆分；找不到能独立检查的边界时，保留原票，写明试过哪些边界、为什么切不开。预备重构单独成票并排在前面。
   常用边界：探针与界面、服务端与客户端、schema 与入口、迁移与核验、包本体与接线、视图与页面。
   完成条件：每张新票有一个可独立检查的交付结果，依赖都写成显式阻断；每张保留的待拆票都写了依据。
4. 重估每张新票。按拆分后的真实范围重算分项和余量，数字如实反映风险；新票仍超过拆分线时，对它再走第 3 步。
   完成条件：每张票的拆分信号在拆分线以内，或带着第 3 步写下的保留依据。
5. 向用户展示新候选票和拆分对应表。逐票表保存到执行 Agent 读不到的位置：目标项目仓库之外，或目标项目约定的规划产物位置且不被任何票引用。批准和发布归 `to-tickets`。
   完成条件：用户能看到每张票的拆分信号、每张原票拆成了哪些新票，以及逐票表的保存路径。
6. 发布前逐票扫描 Issue 标题和正文。
   完成条件：`token`、`100k`、逐票表的列名和具体估算数字在全部 Issue 里零命中。
