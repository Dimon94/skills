# pi-loop PRD

Status: implemented（2026-10-25）

本文件定义 pi-loop 要解决的问题、范围与验收标准。实现结构与取舍归 repo://docs/pi-loop/technical-design.md；使用方法归 repo://skills/pi-loop/SKILL.md。

## 1. 问题

pi 1.4.0 没有内置 `/loop`。需要按节奏重复做的事只能靠人盯着手动重发：

- `issue-sweep` 依赖 Claude Code `/loop` 的自定节奏，每次唤醒跑一轮，由模型决定下次多久后醒。在 pi 里无法运行。
- 轮询 CI、部署、远端队列这类等外部状态的事，需要固定间隔重复同一条提示词。
- 定点任务（工作日早上的日报）需要按本地时间表触发。

npm 上已有两个第三方实现，都不能直接采用：

- `@pwguler/pi-loop`：解析与持久化稳健，但没有自定节奏。
- `pi-cc-loop`：有自定节奏，但用模型解析命令，状态损坏时照常运行（fail-open），没有运行模式检查，发版不跑测试。

两者都会信任仓库里提交的状态文件。拉一个别人的仓库就可能带进循环。

## 2. 用户与场景

用户是在 pi TUI 里工作的开发者本人。

| 场景 | 期望 |
| --- | --- |
| S1 自定节奏扫票 | `/loop auto /skill:issue-sweep wip=2` 立即跑一轮。每轮由模型调用 `loop_next` 决定下次间隔，票清空时调用 `loop_next` 并给出 `reason` 结束循环 |
| S2 固定间隔轮询 | `/loop 5m --max=12 检查 CI` 每轮结束 5 分钟后再跑，最多 12 次 |
| S3 定点任务 | `/loop cron 0 9 * * 1-5 @docs/daily.md` 工作日 9 点按本地时间触发，每次重新读文件 |
| S4 管理 | 列出、暂停、恢复、立即跑、停止指定循环 |
| S5 中断与恢复 | 关掉 pi 后重新打开同一会话，循环继续，不连发 |

## 3. 目标与非目标

目标：

- G1：在 pi 里覆盖 S1–S5，命令语法与 Claude Code `/loop` 的写法接近。
- G2：解析、调度与恢复是确定性的。相同输入与时钟得到相同结果，不依赖模型解析命令。
- G3：失败时停住并说明原因（fail-close）。不静默重发，不猜节奏，不修补坏状态。
- G4：不引入第三方运行依赖；随 Skill 交付，可安装、检查、卸载。

非目标：

- 模型自行新建循环。只有用户能在 TUI 里输入 `/loop`。
- 跨会话、跨机器或后台守护进程调度。pi 不在运行时，循环不跑。
- 补跑停机期间错过的轮次。
- 在 print、json、rpc 模式与子 agent 会话里调度。
- 并行跑多轮。一个会话同一时刻只有一个 agent。

## 4. 功能需求

| 编号 | 需求 |
| --- | --- |
| FR-1 | 三种节奏：`auto`（模型自定）、固定间隔（`90s`、`5m`、`1h30m`、`1d`，范围 1 分钟到 1 天）、`cron`（5 字段，本地时间，日与周同时受限时取并集）|
| FR-2 | 三种提示词：纯文本原样发送；`@path` 每轮重新读文件，内容按纯文本发送，即使以 `/` 开头也不展开；`/skill:name` 与 prompt 模板走 pi 的展开 |
| FR-3 | 拒绝以扩展命令（含 `/loop` 自身）作提示词；`/skill:name` 找不到时当场报错 |
| FR-4 | 选项 `--name`、`--max`、`--until`；名字缺省时由提示词派生并去重；未写 `--until` 时 7 天后停止 |
| FR-5 | 新建后立即跑第一轮；cron 等下一个匹配时刻 |
| FR-6 | 固定间隔从本轮结束时刻起算下一轮；一轮跑超时不连发 |
| FR-7 | `auto` 每轮由 `loop_next` 给出 `delay`（60 秒到 1 天，越界报错，不静默改值）或 `reason` 停表；漏调一次按 20 分钟兜底，连漏两次暂停 |
| FR-8 | 只在会话空闲且无排队消息时派发；忙时让路，空闲后补跑 |
| FR-9 | 暂停条件：Esc 中断本轮；消息发出 30 秒内没开工；提示词文件读不了；`auto` 连漏两次 |
| FR-10 | 动作 `list`、`pause`、`resume`、`run`、`stop`；`loop_status` 工具给模型同样的视图与最近 5 条事件 |
| FR-11 | 状态行显示循环数与各循环的下一轮倒计时或状态 |
| FR-12 | 状态存在会话记录里，跟随分支；重新打开会话时恢复。未到点的循环保留原时刻，中断的一轮从打开时刻起算一个周期，不立即补跑 |

## 5. 非功能需求

- 安全：不读写仓库内的循环状态文件。状态条目逐字段严格校验，坏条目整条丢弃并提示。斜杠提示词只允许 skill 与 prompt 模板。
- 可靠：先写状态再派发，崩溃最多丢一轮，不会重发。长等待按 60 秒分片重算，机器休眠或改时间后不漂移。
- 可观测：每次新建、停表、暂停、恢复都有通知，并进最近事件列表。
- 安装：写 `~/.pi/agent/extensions` 前取得用户授权；安装器拒绝覆盖非 symlink，卸载只删指向本 Skill 的链接（同 repo://docs/adr/0003-skill-owned-agent-hooks.md 第 2、4 节的边界）。

## 7. Unknown

- `issue-sweep` 在 pi 下完整跑一次 coordinator 循环（herdr pi pane 派工 + `SWEEP_DONE`）尚未实测。其节奏规则（有 worker 给 900 秒、都空给 1800 秒、前置门失败给 reason）已用本地替身 skill 验证映射正确。另外它现在放在 `.claude/skills/` 下，pi 不扫这个位置，要用需先迁到 `.agents/skills/`。
- cron 在夏令时切换当天的行为未验证；本机时区无夏令时。
