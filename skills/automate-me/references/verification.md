# 前向验证案例

在隔离项目和假的历史会话记录上重放。评估会话只获得输入、当前 Skill 和可用的项目规则；实际产物逐条核对。静态链接检查不证明这些行为已通过。

## 主路径：其他使用者创建自己的个人工作方式 Skill

输入：使用者句柄为 `linus`，目标项目尚无 `skills/linus-mode/`。两个独立时间片都要求先给文件坐标、简洁中文和只读验证；另有只在某项目出现一次的部署偏好。目标项目已有写作规范、工作树规则和一个项目专属 Skill。

核对实际产物：

- 使用 `automate-me` 的公开流程，而非调用别人的个人 mode；创建 `skills/linus-mode/`，其规则不依赖 Dimon 或其他使用者的 mode。
- 重复偏好带适用分支、时间片和来源；单次部署偏好保持候选或进入项目规则，不冒充个人通用规则。
- 目标项目的分支、写作与显式调用规则得到遵守；已有 Skill 通过指针复用，正文未被复制。
- 读回实际文件与 diff，执行项目校验；不自动提交、推送或合并。

## 关键失败路径：增量更新保留旧决定，只加入新证据

输入：已有 `skills/linus-mode/`，上次变更有可定位锚点，旧规则要求先给验证命令。新历史只有一个时间片提出改用英文，另有多个时间片重复要求审查时先列具体文件和行号。跨会话工具可用；旧规则未涉及的分支不扩大。

核对实际产物：

- 只处理上次变更之后的证据，保留旧验证命令规则和无关章节。
- 英文偏好仍是单次候选，先与用户校准；文件与行号要求在确认后才成为规则，来源与适用分支可追踪。
- 冲突未被静默覆盖；最终只修改获准的目标 mode，保留实际产物、差异和未确认项。

## 留存证据

记录历史来源、时间片、候选清单、用户确认、实际文件、目录 diff、静态校验及案例结果。未执行的案例标为未验证；跨会话工具不可用时记录阻塞与补证据入口，不声称完成创建或增量更新。
