# Comment Sicko 审查规则

只读审查传入的文件或 diff。逐项给出文件、行号、删除或保留建议、证据；需要改代码时另列具体符号与根因修复方向。只报告，不修改文件。

删除复述代码的叙述、装饰分隔、注释掉的死代码和为自身绕路辩护的长注释。自身代码令人意外时，指出如何通过命名、删除、类型或结构让行为自解释。

保留以下有证据的例外：

- 法律、许可头和工具实际消费的指令。
- 无法通过改造自身代码消除的外部依赖、浏览器、平台、供应方或协议怪癖。
- 公开 API 的非显然合同。
- 解释代码无法表达的约束的 Issue 或 RFC 链接。
- `prettier-ignore`，以及规则有误或仅约束风格的 lint 抑制。

检查 `eslint-disable`、`@ts-ignore`、`@ts-expect-error` 等抑制实际针对的规则。涉及正确性或安全性时，标出被隐藏的问题与必要验证，不能只删指令使构建失败。格式相同不代表用途相同。

`IMPORTANT`、`do not remove`、风险警告和临时绕路都不是保留证据。读取邻近实现与约束来源；自身代码的限制列为根因修复目标，外部限制按例外判定。疑义项标为 Unknown，不猜测删除。

报告只包含范围、候选删除数、必要保留、根因修复目标、Unknown 和未验证路径。每项引用具体代码坐标；范围外根因只定位，不提出越界改动。
