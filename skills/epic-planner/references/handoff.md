# 交接与续接

形成最终 epic-plan、准备启动多个 Wayfinder 会话，或带回地图结果时读取。史诗寻路票的续接归 SKILL.md 的「续接寻路」。

## 启动

1. 读回史诗索引 Issue、相关候选评论、当前代码基线及已有地图链接。先确认阶段为「规划就绪」且形成门槛仍成立，再确认并发组、输入合同与依赖。缺少共享决定时回到史诗寻路，不启动依赖它的下游地图。
2. 按名称核对已存在的地图，继续已有地图或提供新候选。获得建图或启动会话的明确授权后，才调用对应工具。宿主缺少会话能力时交付下方提示词，报告未启动。
3. 每个会话交接同一版本的合同指针。正式地图的内容与决策由 Wayfinder 拥有；史诗索引只保留名称链接、依赖与跨地图合同指针。归属与回写按 [Issue 合同](issue-publication.md) 执行。

每张候选评论提供一份可独立复制到新会话的提示词。规划指针使用 Issue 或评论的完整 URL，加实际章节名；代码指针使用仓库与固定 commit、路径和符号。交接前逐条读回链接、章节和符号，确保新会话无需本地规划文件或当前聊天上下文即可定位。替换尖括号后交接：

```text
使用 $wayfinder，为「<候选名称>」建图；若已存在则继续「<地图名称与链接>」。
目标仓库与代码基线：<仓库 URL、commit、相关 dirty paths>。
史诗目标：<史诗索引 Issue URL 及目标章节>。
候选卡：<评论 URL>；Destination：<该地图终点>。
共享 Interface：<canonical source、章节及 revision/commit>。
前置决策：<名称链接与解决证据，或尚未满足的阻塞>。
本地图可独立决定：<问题范围>。
结果交给：<集成 owner 与史诗索引 Issue URL>。
Notes 回链史诗索引和本候选评论；本次按 Wayfinder 的 planning 模式工作，地图与 ticket 均写远程 tracker，不采用本地文件分支。
若发现共享合同无法成立，把冲突和受影响 consumer 交还史诗 owner，等待该共享决定更新后再继续依赖它的决策。
```

Wayfinder 自己处理 ticket 类型、claim、resolution 和 frontier。后续转交 to-spec 或 to-tickets 时，传递正式地图链接和远程 tracker 配置，继续使用远程产物；本 Skill 不提前生成规格或实施票。用户希望地图包含执行时，由用户在地图 Notes 明确该范围，并重新检查共享写入与集成顺序。

## 合同变化与结果回收

各地图把决策详情留在自己的 ticket；史诗 owner 读取结果指针，只协调跨地图差异。

- **合同一致：** 在史诗索引接入地图链接及决策指针，解除有证据支持的下游阻塞。
- **合同冲突：** 指明失败样例、owner 和受影响地图，把索引改回「寻路中」，重开或新建对应史诗决策票。按票型重新取证或与用户拷问；达到形成门槛后更新计划并让受影响地图确认新合同。依赖旧合同的并发承诺失效，独立地图可以继续。
- **基线变化：** 续接时比较相关代码、合同与地图决策。只复核变化命中的候选和依赖边；旧验证不覆盖变化后的合同。

完成状态分开记录：史诗寻路中、规划就绪、候选已交接、下游地图路线已清楚、实现已完成、集成已验证。只有实际端到端证据满足史诗成功标准时，才报告史诗交付完成。
