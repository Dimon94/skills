# 提前规划 Cycle

入口：用户安排下周或指定未来一周时执行。完整排期包含周期名称、目标说明和所选 Issue 归属；只要方案的请求停在只读候选。沿用本会话已确认的团队、目标与写入授权，补齐缺的动作，不逐项再问。本 Skill 不调用开发派发，原自动调度继续。

## 1. 绑定范围与目标周

读取真实当前时间，以 Asia/Shanghai 确定下周一 00:00 至再下一周一 00:00；用户指定日期时使用该周并写出绝对日期。通过官方 Linear MCP 解析 Team、项目与 Cycle ID，完整分页；仅给 Team 时覆盖该 Team 的项目，不任取一个项目。每个 Team 使用自己的 Cycle，各项目共用该周期。

读回 Cycle 的实际起止时间，按目标周精确匹配已有 Cycle。复用已有对象；名称相同不证明日期相同。界面的周日结束日与 API 下一周一 00:00 是同一周的两种显示。

完成：每个 Team 有目标周、项目范围和目标 Cycle，或明确的缺期／配置差异。未来 Cycle 的 Upcoming／Planned 状态允许继续规划。

## 2. 形成工作集合与目标

读取进行中、待审、待验收 Issue，以及已选目标的父项、子票、依赖和原交付记录。对照既有 Cycle 归属与专用剔除标签；父项标记按 SKILL.md「剔除与恢复」继承。规划本身不创建排除标签；未配置时如实报告。

- 进行中的工作默认纳入，周内做不完也保留。所选下周目标及其待推进子票可以提前排入，包括 Backlog；其依赖保持原样，排期不等于解除阻断或授权开工。
- 未选且未开始的兄弟票保留原排期；已完成／取消项不新增到未来周。一个 Issue 只属一个 Cycle：已有本周归属的工作列为结转候选，先保留本周历史，新周再由本周维护入口判断；已排其他周的工作也保留。只有用户明确改排该项时才提前迁移。
- 回源原 Spec、正文与父子关系识别 MMF；标题或层级本身不足以证明身份。编号标题等脚本识别缺口不改变原 Spec；原生规划可按已核实的合同安排，脚本缺口另报。独立 Bug、调研可以作为工作项排入，MMF 归属不明就不计入正式交付。Epic 保留跨期总览；测试样本只在明确的测试范围内排入。
- 多 Team 分开形成目标，审查与验收精力一起分配；重点目标的取舍不替代全部进行中工作集合。目标调整保留原因，未完成工作延续原 Issue、分支与现场。正式交付仍使用 SKILL.md「正式交付」的唯一判断。

完成：每项候选有真实 ID、来源、目标周与纳入理由；工作项数量和 MMF 数量分开。只读请求在此交付建议与待执行变更。

## 3. 准备原生周期

在获授权的范围内核对单周、周一开始、Asia/Shanghai、无 cooldown。用原生配置／创建能力补齐目标 Cycle；团队配置仍由 Linear 拥有。团队改配必须有明确授权，未授权时先列出精确差异与变更草案，不把双周截半或提前命名成单周；其他 Team 继续处理。

优先使用官方 MCP。工具没有改配、命名或描述能力时，使用已登录的 Linear 界面；只有真实能力／权限不足才阻断该动作，不把缺少 MCP 工具误报为 Linear 不支持。缺目标 Cycle 时按现有授权使用原生创建或自动创建设置，不新建周期引擎。

新增名称使用 `YYYY-MM-DD｜周期主题`，主题来自本轮选定目标；保留已有自定义名称与有效目标，按新决定增量更新。描述与对话展示按 [周期呈现](cycle-presentation.md) 组织。配置、名称和完整描述保存后读回，按表单限制精简被截断的内容。

完成：目标 Cycle 的起止时间、名称、说明已落地并读回；缺授权或能力的变更有独立待办，不能阻断已经允许的其他准备。

## 4. 提前排入 Issue

只读建议或周期尚未核实的 Team 不执行本步。完整排期使用目标 Cycle 的真实 ID，通过 `save_issue {id, cycle}` 逐项安排；不借当前周 CLI 的时间门禁操作未来周，也不模拟未来时钟。

每项写前重读范围、状态、排除标记和原周期；已在目标 Cycle 则跳过，已完成／取消或出现新冲突则保留现场。写入只传 ID 与 Cycle，不提交依赖、标签、正文或工作流字段。写后回读 Cycle 归属及原有字段；不以保存成功或 HTTP 状态作为完成依据。

**Backlog → Todo 是 Linear 原生排期行为。** 在本次已授权排期内接受并报告；不设置 In Progress，不另行派发开发。把 Todo 改回 Backlog 会清掉 Cycle，不能通过来回改状态维持假排期。其他状态变化先核对最新事实／状态历史，保留并发开发进展，不按旧快照回滚。

首次回读未确认时先重读；仍不符或不可读就记录未知／失败及已成功项。重试先读当前归属，只补未生效项，已确认的结果不回滚。

完成：每个所选 Issue 已在目标 Cycle，或有保留原周期、失败／未知的具体原因；状态的原生变化单列。

## 5. 核对整周结果

按每个目标 Cycle 完整分页列出 Issue，与所选集合核对遗漏；父子项可以展开，正式交付按 MMF 去重。已有且本轮未选择的周期成员保持原位。报告周期链接、日期、目标、已排 Issue 数、原生状态变化及剩余差异。

完整排期成功必须同时具备周期准备和 Issue 归属的读回证据，不能只命名、只写说明或只给清单就结束。提前排期与真实运行验收分开：原生排期成功不证明本周脚本、跨周结转或正式交付已验收。任何缺口按实际原因报告，不因周期尚未开始而推迟能执行的准备。
