# 前向验证案例

给独立会话 SKILL.md 路径与下列输入，不给预期答案；按检查项判定实际输出。没有 tracker 与发布授权，输出应是未发布的切片清单。

## 共用输入：领券抵扣 MMF 的 Spec

电商项目新增优惠券，`to-epic` 已把它切成多个 MMF。本 Spec 是第一个 MMF「领券抵扣」，验收标准：

1. 运营在后台创建满减券：面额、门槛、有效期、总量。
2. 用户在商品详情页领券，每人限领一张，领完总量即止。
3. 下单时自动选中可用的最优券，订单金额扣减。

代码事实：订单金额由 `OrderPricing` Module 计算，Interface 为 `price(cart) -> Quote`；用户中心与商品详情页已上线；无券相关表；项目有 feature flag 服务。

## 主路径：默认模式切分

检查：

- 第一片是 walking skeleton，只覆盖核心闭环（创建、领取、下单抵扣）：一张硬编码或后台最简创建的券，用户能领取，下单时能看到抵扣。一片只建表、只做 API 或只做后台页面，均失败。
- 每人限领、总量、后台完整建券各自成片；`OrderPricing` 的 Interface 变动落在骨架或其前置结构片里；加厚片只在 seam 后补变体。
- 每条阻塞边写明依赖的 Interface 或能力；至少两张加厚片之间没有阻塞边，可以并发。
- 三条验收标准都落到某一片，或列入延后、丢弃并写理由；不存在「联调」「集成」「上线」票。
- 每片的可检查结果都写成「谁 · 入口 · 做什么 · 看到什么」。
- 票不单独合入 main、不单独部署；输出没有里程碑、release toggle 或收尾片，执行交接是本 MMF 一个 MR 一次合入上线。
- 第 6 步只标波次，不在估算前判 MMF 是否超限。
- 交付顺序：先给切片表，再给 `ticket-sizing` 的每票拆分信号和本 MMF 的票数与拆分信号合计，写出推荐（照此执行、重切或转例外模式）与理由，然后停下等用户三选一。在用户看到票数与合计之前请求 `/to-tickets` 即失败；拿某个合计阈值替用户裁决即失败；没有推荐或没有理由即失败。估算措辞用拆分信号，不写预算或上限。

## 用户三选一

输入同主路径，分别给三条用户回复，各开一个会话续跑。

检查：

- 回复「照此执行」：有票超过拆分线时先请用户运行 `/ticket-split-100k`，再请用户运行 `/to-tickets`；没有出现例外产物。
- 回复「重切」：停下请用户运行 `/to-epic`，列出切片表、拆分信号与合计；没有请求 `/to-tickets`。
- 回复「切不开，逐票合入」：转入下一节的例外模式。

## 例外模式触发

输入同上，另给事实：用户看过票数与拆分信号合计后，确认本 MMF 切不开、又要逐票合入。

检查：

- 输出读取并按 references/release-per-ticket.md 执行；每片可独立部署，有 small batch 判断与依据；依据是拆分信号与拆分线，不是开发时长估计。
- 用户可见部分有隐藏手法，并有对应收尾片。
- 每片有波次号与所属里程碑；里程碑 1 含骨架与防资损规则（每人限领、总量），放量对象是外部目标用户。只放内部账号的里程碑 1 失败。
- 每个里程碑有放量对象、验收人与验收结果，以及自己的 release toggle 收尾片；单一 toggle 覆盖到最后一片即失败。
- 没有这条事实时（主路径），出现上述任一例外产物即失败。

## 单票短路

输入：另一个 MMF 的 Spec「券包页标灰过期券」，只有一条验收标准：券过期后在用户券包里标灰、不可选；券表已有 `expires_at`。

检查：

- 判定为单票短路并写出依据：切不出第二个可单独检查的结果，一个上下文装得下。
- 没有切片表、没有调用 `ticket-sizing`、没有请用户运行 `/to-tickets`；停下请用户对这份 Spec 运行 `/implement`。

## 输入不止一个 MMF

输入：在共用输入上追加验收标准「退款时按比例退回已用券的抵扣」和「运营查看每张券的领取与核销报表」。

检查：

- 判定输入不止一个 MMF（报表单独上线也有人用），停下请用户运行 `/to-epic`，列出识别出的 MMF 候选；没有直接把六条标准切成票。

## 关键失败路径：审查横切拆票

输入为共用输入，另给一份既有拆票：① 建 coupon 与 user_coupon 表 ② 券 CRUD API ③ 后台券管理页面 ④ 领券接口 ⑤ 前端领券 ⑥ 订单接入优惠券 ⑦ 全链路联调与上线。

检查：

- 逐票报出未过的切片检查项，至少点名 ①②③ 无可检查结果、⑦ 是集成票。
- 指出缺少端到端骨架，给出以骨架为第一片的重切方案；方案含切片表，三条验收标准都有落点。
- 不把「全部票随 MMF 一次合入」报为 finding。
- 每条 finding 指向票号与检查项。

同一检查先用于修改前的输出，再用于修改后的输出。通过只说明这些路径的形状正确，不证明真实项目里的尺寸判断与依赖准确。

## 关键失败路径：同波次两片写同一目标

输入同上，另给代码事实：券类型由 `coupon/types.ts` 里的一张 `COUPON_TYPES` 注册表登记；新增迁移文件名按全局递增序号命名（如 `0042_add_coupon.sql`）。Spec 追加验收标准：4. 支持折扣券；5. 支持无门槛券。

检查：

- 折扣券、无门槛券各成一片且同波次时，两片不共同改 `COUPON_TYPES` 这一张表：输出改成每种券类型自己一个文件、由注册表在读取边界汇总；或写明为什么必须共用并把登记合进一片或连边。只在票里提醒「注意另一片也在改」即失败。
- 两片都要新建迁移时，点名「迁移序号全局递增」是单写者不变量，给出结构化串行：连阻塞边，或把建表迁移集中到前置片。两片各自生成迁移、同波次并发即失败。
- 依赖边的说明写明它依赖的是 Interface、能力还是单写者不变量。
