# 前向验证案例

修改决策路由、切分、并发、范围或交接规则时，用隔离项目和假的 tracker 重放。给评估会话原始输入及事实，按实际输出判断；产品目录和真实远程保持只读。格式与链接安装检查只证明 Skill 可读取，不证明下列行为已经通过。

## 主路径：独立形成首个 MMF 与并发候选

输入：用户已批准销售、退款和定时导出的整体结果；目标项目已有代码、已知账目和下载入口。首份销售导出会建立后续需要的生成结果 Interface；退款台账能力已可核对，定时执行的授权与任务语义已明确。净额核对依赖的快照仍未知，但不影响前三项。环境没有 delivery-pipeline 配置，tracker 未配置发布位置。

核对实际产物：

- 交付目标、约束和 MMF 候选，首个 MMF 贯通生成、下载与账目核对。每项批准结果都有去向；净额未知保留在相关候选中。
- 每个候选写明两条切分测试的答案与依据。生成结果 Interface 作为结构票放进首个 MMF，不单列成 MMF。
- 读取 codebase-design 并按相关 Module、Interface、Seam 检查切分；MMF 不按数据库、前端等技术层分组，也不机械对应新 Module。
- 每个候选都有 `Blocked by`（含 `无`），每条边有开工或上线类型、依据与解除证据。退款与定时对销售导出是上线边：生成结果 Interface 对齐后与首片并发开发；净额核对对快照是开工边，排在后续波次。
- 向用户展示开工波次，看得出哪些候选并发、哪些串联。
- 在当前会话交付未发布草稿和交接输入，复用已有确认。工作区无计划稿，tracker 无写入。
- 改由编排方调用：停下时以 `NEXT: to-spec <候选与理由>` 一行交回调用方并列出同样的交接输入，不对用户说「请运行」。

## 按问题推进：选机数据与每日报价

首轮输入：「对标站有机房、计费周期、库存和线路数据，希望补齐数据并每天更新报价。用 to-epic 规划。」隔离项目已有 Plan 数据、首页比较表和只探测库存的刷新入口。假的 Provider 官方目录能精确匹配现有 Plan 的产品、机房、周期与价格，三网实测还没有可信样本。假的 tracker 已配置。

按轮次提供反馈：

1. 用户批准首批面向从大陆连接海外 VPS 的开发者。报价缺少当前证据时保留历史日期，退出可买排序。官方数据校验通过就每日自动发布。三网实测后置。用户确认整体目标和候选范围，但尚未授权发布 Issue。
2. 用户授权在假的 tracker 发布 Epic Issue，并选择把首个就绪 MMF 交给要求 Spec Issue 的交付入口。

核对实际产物：

- 在第一轮自行读刷新入口和官方目录，基于发现提出会改变范围或验收的具体问题和推荐。发布规则的问题以官方目录可精确匹配为前提。已有证据足以选首个 MMF，直接使用证据。
- 复用已确认决定。首个 MMF 贯通每日核价、发布与页面读回，三网实测保留在后续候选。已决定事项与来源进入同一份 Epic，不生成决策地图或研究子 Issue。
- 第一次交付注明草稿未发布及缺项，tracker 写入 0 次。获授权后创建 1 张 Epic Issue，读回正文并返回标题和 URL，再提供首个 MMF 的 Spec 交接材料。
- 变体：比较表在窄屏如何展开多个周期的实付价格，会改变首个 MMF 的验收，项目没有可体验的样例。先做隔离原型供用户裁决。把用户选定的行为写回同一份 Epic，再继续拆分。

## 已发布 Epic 交接

输入：tracker 已配置，用户授权发布。两个已确认 MMF 可并发，其中一个有上线依赖。已有第三项的 Spec 链接。

核对实际产物与写入：

- 唯一持久计划是 Epic Issue。逐项读回稳定 MMF 标识、两类依赖、解除证据与原 Spec 链接。
- 交付 Epic 链接和开工波次，用户可将链接交给任一支持 Epic 的交付入口。无本地计划稿。

## 关键失败路径：反馈只改变部分候选

输入：已有 Epic、正式 Spec 链接和获批范围；本轮只获准更新假的 Epic。新对账证据表明退款候选的日期口径不成立，另一份下载记录查询的 Interface 和验收不受影响。已有执行中的候选使用旧口径；新的业务口径尚待用户取舍。

核对实际产物与写入：

- 定向标明证据、受影响验收和依赖；协调已开工工作，向用户提出具体口径取舍与推荐。保持无关候选的有效决定和可推进状态。
- 保留正式 Spec 链接和全部批准结果；不把未决结果静默删掉，也不将规划更新写成 Epic 已交付。
- 按共同的 Epic 认领合同先取得写入权、再读回原文；若已有活跃 coordinator，由其写回。只更新授权的 Epic 并读回；不重建已有条目、改写正式 Spec、创建 MR 或修改产品源码。写入失败时报告已成功坐标和待恢复动作。

## 入口缺术语：转交 reframe

输入：「想让客服回复更快，用 to-epic 规划。」隔离项目的 GLOSSARY 没有能命名该目标的词条，代码里也没有对应能力。

核对实际产物：

- 停在第 1 步，请用户运行 `/reframe`，不自造术语切 MMF，tracker 写入 0 次。
- 改由编排方调用：以 `NEXT: blocked-human 目标缺专业术语，需用户运行 /reframe` 一行交回。
- 变体：输入已是 reframe 重写后的描述，新术语标「待入 GLOSSARY」。沿用该描述定目标，不再转交。

## 留存证据

行为重放记录输入、实际产物、tracker 变更、目录差异和未通过项。未执行的案例标为未验证。安装验证另核对两个运行时的 symlink、名称与显式调用策略，以及旧名称已退出。
