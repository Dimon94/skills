# 前向验证案例

给独立会话 SKILL.md 路径与下列输入，不给预期答案；按检查项判定实际输出。没有 tracker 与发布授权，输出应是未发布的切片表。确定性部分另有 `node --test skills/to-tickets/tests/check-tickets.test.js`，其中 DD-455 回放夹具记录了旧切法（7 波）与合同先行（6 波、同波重叠 8→1）的对照。

## 共用输入：领券抵扣 MMF 的 Spec

电商项目新增优惠券，`to-epic` 已把它切成多个 MMF。本 Spec 是第一个 MMF「领券抵扣」。Business Flow：T1 运营创建满减券（面额、门槛、有效期、总量）；T2 用户在商品详情页领券；T3 下单时自动选中最优券并扣减。R1 每人限领一张；R2 领完总量即止。User Stories 1–3 对应 T1–T3。Implementation Decisions：`CouponStore` Owns T1、T2、R1、R2；`OrderPricing` Owns T3，Interface 为 `price(cart, coupons) -> Quote`（由 `price(cart) -> Quote` 改动）。

代码事实：用户中心与商品详情页已上线；无券相关表；项目有 feature flag 服务。

## 主路径：合同先行

检查：

- 第 1 波只有合同票：含 `price(cart, coupons)` 新签名与桩、券表 schema 与迁移、验收夹具；不实现 T1–T3。合同票实现了领券或抵扣即失败。
- 行为票各自 Owns T1、T2、T3；R1、R2 各有唯一 owner（领券那张），其他票写 `Respects`。同一 R 出现在两张票的 Owns 即失败。
- T1、T2、T3 三张行为票只依赖合同票，同在第 2 波并发；T3 的验收用夹具里的券，不阻塞于 T1。T3 因「调用券 Interface」连到 T1 即失败。
- 不存在「联调」「集成」「回归」「上线」票；没有空的行为票。
- 第 6 步运行了 `check-tickets.js`，零 `error`，输出了 waves 与 critical-path。
- 第 7 步展示切片表、波次与关键路径、`ticket-sizing` 每票拆分信号与合计、推荐与理由，然后停下。在用户选定前请求发布即失败；拿合计阈值替用户裁决即失败。票面出现 token 数字即失败。

## 编排调用

输入同主路径，另说明本次由编排方调用（调用输入是编排 Action）。

检查：

- 第 7 步停下，把切片表、波次与关键路径、拆分信号与合计、推荐与理由和草稿路径交回调用方；不发布。直接对用户说「请运行 `/to-epic`」或自行发布即失败。
- 选「重切」时交回 `NEXT: to-epic <理由>` 一行。

## 用户三选一

输入同主路径，分别给三条用户回复，各开一个会话续跑。

- 「照此执行」：有票超过拆分线时先按 `ticket-sizing`「拆分线」拆开，再发布；没有例外产物。
- 「重切」：停下请用户运行 `/to-epic`，列出切片表、拆分信号与合计；不发布。
- 「切不开，逐票合入」：转入例外模式。

## 例外模式触发

输入同上，另给事实：用户看过票数与拆分信号合计后，确认本 MMF 切不开、又要逐票合入。

- 输出读取并按 references/release-per-ticket.md 执行；每片可独立部署，有 small batch 判断与依据；依据是拆分信号与拆分线，不是开发时长估计。
- 用户可见部分有隐藏手法，并有对应收尾片。
- 里程碑 1 含合同票、核心闭环与防资损规则（R1、R2），放量对象是外部目标用户。只放内部账号的里程碑 1 失败。
- 每个里程碑有放量对象、验收人与验收结果，以及自己的 release toggle 收尾片；单一 toggle 覆盖到最后一片即失败。
- 没有这条事实时（主路径），出现上述任一例外产物即失败。

## 单票

输入：另一个 MMF 的 Spec「券包页标灰过期券」，只有 T1 与 R1，没有 Interface 改动；券表已有 `expires_at`。

- 不设合同票；切片表只有一行，该票 Owns T1、R1，`Blocked by: None`。
- 仍运行核对脚本、调用 `ticket-sizing`、请用户裁决后再发布。直接请用户运行 `/implement` 即失败。

## 输入不止一个 MMF

输入：在共用输入上追加「退款时按比例退回已用券的抵扣」和「运营查看每张券的领取与核销报表」。

- 判定输入不止一个 MMF（报表单独上线也有人用），停下请用户运行 `/to-epic`，列出 MMF 候选；没有直接切票。

## 关键失败路径：审查横切拆票

输入为共用输入，另给既有拆票：① 建 coupon 与 user_coupon 表 ② 券 CRUD API ③ 后台券管理页面 ④ 领券接口 ⑤ 前端领券 ⑥ 订单接入优惠券 ⑦ 全链路联调与上线。

- 逐票报出未过的切片检查项或脚本规则，至少点名 ①②③ 无可检查结果、⑦ 是集成票、R1/R2 无唯一 owner。
- 重切方案为合同票（含 ① 的 schema 与 ⑥ 的签名）加并发行为票，附切片表与脚本输出。
- 不把「全部票随 MMF 一次合入」报为 finding；每条 finding 指向票号。

## 关键失败路径：同波共享写入目标

输入同上，另给代码事实：券类型登记在一张 `COUPON_TYPES` 注册表；迁移文件按全局递增序号命名。Spec 追加 T4 折扣券、T5 无门槛券。

- `COUPON_TYPES` 新增的两个变体与两张票的迁移都前移到合同票；T4、T5 两张票同在一波并发，不再写注册表或迁移。只在票里提醒「注意另一片也在改」即失败。
- 两张票各自新建迁移且同波并发即失败。

同一检查先用于修改前的输出，再用于修改后的输出。通过只说明这些路径的形状正确，不证明真实项目里的尺寸判断与依赖准确。
