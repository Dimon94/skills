# Thinking Model

用途：根因诊断、互斥方案取舍和方案落地前推演。

## 1. 三层诊断

现象层：

- 输入：错误、堆栈、用户现象和运行状态。
- 目标：锁定可复现症状和最小止血动作。

本质层：

- 输入：多个现象和系统约束。
- 目标：找到少数根因，解释为何发生。

设计层：

- 输入：候选方案和不变量。
- 目标：验证方案因果链、负效应和回退条件。

输出顺序：现象 → 根因 → 设计不变量 → 最小动作。

## 2. TOC 五聚焦

触发：系统反复修不好、吞吐被卡住或优化没有效果。

1. 识别约束：找限制全链路结果的唯一瓶颈。
2. 挖尽约束：先消除空转、返工和错序。
3. 迁就约束：让其他环节服从约束节奏。
4. 提升约束：前三步用尽后才增加资源。
5. 回到第一步：约束解除后寻找新约束，删除旧沉积规则。

完成标准：给出约束的具体坐标，并解释其他候选为何不是约束。

## 3. 当前现实树

触发：多个不良现象可能共享根因。

1. 列出 3 至 10 个可观察现象。
2. 用 if-then 连接因果链。
3. 向下追到不超过 3 个核心根因。
4. 校验每条边：
   - 措辞清晰。
   - 实体存在。
   - 因果存在。
   - 原因足够。
   - 没有隐藏的附加原因。

完成标准：核心根因能解释至少 70% 的现象，每条因果边有证据。

## 4. 冲突云

触发：两个方案互斥，讨论开始滑向折中。

1. 写出两个互斥动作。
2. 写出各自动作满足的需求。
3. 写出两个需求共同服务的目标。
4. 补全“因为……所以必须……”的隐藏假设。
5. 找到可证伪假设，加入新条件消除冲突。

完成标准：给出非折中方案；或证明假设均成立，并明确取舍理由。

## 5. 未来现实树

触发：方案落地前验证预期效果。

1. 从实施动作出发，用 if-then 推演到期望结果。
2. 检查每条因果边是否成立。
3. 主动寻找负效应分支。
4. 为每个负效应添加修剪动作。
5. 无法修剪时回退方案或明确接受风险。

完成标准：期望结果有完整因果链；全部负效应有处理或接受记录。

## 6. Unknown 管理

把未知分为：

- 已知事实。
- 已知缺口。
- 未验证假设。
- 无法预见风险。

工作时先补会改变当前方案的已知缺口。其他 Unknown 留在风险记录。不要用更多抽象掩盖未知。
