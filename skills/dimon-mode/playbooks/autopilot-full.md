# 多 PR 无人值守到合并

总控只管验证与门禁，绝不直接改产品代码。每个 PR 由唯一 owner 从实现带到落地；在未写该代码的独立验证者证明即将落地的代码之前，任何 PR 不得合并。

外部宿主经 Herdr 调度时，运行期账本、布局、模型启动与事件唤醒由 [`herdr-autopilot`](../../herdr-autopilot/SKILL.md) 承载；本剧本拥有多 PR 无人值守的验证、合入前判定、门禁完整性和卡死替换合同。只验证不合并或有依赖栈时，改走 [`autopilot-stack.md`](autopilot-stack.md)。

1. **操作者门禁永远第一。** 授权仅覆盖本次明确入队的项；操作者声明自己负责的项与队列外 PR 止于 merge-ready。询问计划不是开工授权；合并 PR 等不可逆动作只在获得明确授权后执行，无授权即停在 `awaiting_merge`。
2. **一 PR 一 owner，独立工作树，主干平行拉出，状态持久可接管。**
   - 每个 PR 在独立工作树（[`git-worktree`](../../git-worktree/SKILL.md)）中直接从主干拉出、平行推进，不叠栈（叠栈仅在 `autopilot-stack.md` 生效）。
   - 早开 PR（[`git-push-pr`](../../git-push-pr/SKILL.md)），让 CI 与自动化审查尽早并行运行。
   - **Code-ready 门槛**：提交给独立验证前，先清理冗余与 AI 腔并跑 `/no-comments`（或按项目注释规范清理叙述注释），rebase 到当前主干，在已提交 head 上跑受影响路径的检查，然后向总控报告 code-ready head。后续修补回合留在该 base 上，除非主干冲突、破坏 CI 或改了同一批文件，避免无谓重启 CI。
   - **假定 worker 随时崩溃**：开工后尽早 push 并在持久账本/决策记录中留痕，每个完成单元先 push 再开工下一单元；派生子代理时记下 ID、状态和 `stuck-after` 超时阈值，供总控在父节点挂掉后探活接管。Owner 只对自己的分支使用 `git push --force-with-lease`（锁定上次自己推送或接管的 SHA），遇到非本人产生的远端推送立即停下上报总控。
   - Owner 按 [`babysit.md`](babysit.md) 把 PR 清到全绿；唯一例外是遇到需要 rebase 时，由 owner 自己 rebase 并 `--force-with-lease` 推送。
   完成条件：每个 PR 都有明确 owner、独立工作树、已报告的 code-ready head 与可追溯记录。
3. **独立验证只做一次全量。**
   - 在 code-ready head 启动独立于作者的验证（[`code-review`](../../code-review/SKILL.md) 叠加真实界面的 `verify-*` 或命名驱动验证与 diff 审计）。仅当出现新行为、重新设计或大面积新 diff 时重跑全量；纯 rebase、解冲突或小修补只跑定向验证，纯措辞改动不重跑。
   - 缺少真实界面验证（适用时）或未核对 merge-ready 报告中的实测凭据，verdict 不算干净。
   - **基线既有问题不阻断**：只为本 PR 新引入或新触达的可复现问题（用户会踩的缺陷、失败门禁、被 PR 改错的文档）阻断；base 已有的问题转后续跟进。
   完成条件：每个 PR 拿到绑定当前 patch 的独立 verdict。
4. **合入前按主干增量分类，只合并已验证且针对落点测试过的代码。** 绿 CI 本身不授权合并；新 head 仍需自己的绿 CI，rebase 后的 verdict 延续按 [`shipping.md`](shipping.md) 第 3 步判定。合并前 fetch 主干，按主干变化分类，避免无限 rebase 循环：
   - 存在冲突、双方改了同一文件，或改变了本 PR 触发的检查集合：rebase 到最新主干并等新 CI 全绿。
   - 仅双方改了 lockfile：在合并结果上运行冻结安装且本 PR 变更的依赖解析一致时，无需 rebase；安装失败则 rebase 修复。
   - 主干改动了本 PR 的调用方或被依赖模块/版本：在合并结果上重跑本 PR 检查，通过即可合并。
   - 主干改动与本 PR 无关：直接走 [`gh-merge-pr`](../../gh-merge-pr/SKILL.md)（含预览门与收尾）合并。
   - 若 merge-prep 之后主干连续触发第 3 次 rebase：停下上报总控，由总控串行编排碰撞任务。
   完成条件：已授权且通过主干增量判定的 PR 读回 `MERGED` 并完成收尾；其余停在 `awaiting_merge`。
5. **总控层守门与按副作用判卡死。**
   - **放宽门禁必经证明与复签**：提高预算、加白名单、放宽阈值必须先有独立验证者证明，再由总控重新复签（owner 有天然动机求绿）；禁用或软化必过检查一律退回。绝不绕过平台强制审批。
   - **按副作用判卡死，不信自述文本**：巡检下探到每个 worker 与叶节点，只认真实副作用（新 commit、push、账本/轨迹更新、工具活动），不轻信状态标签或摘要。出现报错、无法起轮、超过 `stuck-after` 无新副作用，或首轮巡检既未 push 又未落痕即判卡死，**立即替换而不等旧停止动作落地**。正在等待总控或操作者答复的不算卡死，直接答复推进。
   - **静默巡检**：本轮巡检未改变对操作者可见的状态时保持安静；有变化时只汇报增量。
6. **操作者叫停即刻零写入。** 收到停止指令，立刻向每个 owner 下发零写入暂停令；各 owner 汇报当前位置并保留任务简报，等待释放。

回复写五项：每个 PR 的当前状态与 verdict；已合并清单及链接；总控复签项与理由；等待操作者拍板的门禁；延后跟进项。
